# WhatsApp Order Updates for Indian Retail: Event-Driven Design

*Research snapshot: 26 November 2026.*

**Editorial disclosure:** This is a workflow pattern, not a delivery or conversion guarantee. Confirm current Meta template and account rules.

## Make the commerce system authoritative

Send an order confirmation, dispatch event, delivery update or return status only from a durable order event. Do not let a chatbot invent a shipment date or mark an order delivered. Store the event version, order ID, customer identity, template and send decision.

Meta's [WhatsApp Business Platform documentation](https://developers.facebook.com/documentation/business-messaging/whatsapp/overview) covers templates, messaging and webhooks. Build idempotency around the order event so a provider retry does not send the same update twice.

## Failure handling

Use a dead-letter queue for missing addresses, invalid customer IDs, template failures and provider timeouts. A human should be able to inspect the order, suppress a message and contact the customer. Keep support links short-lived and authenticated.

## Failure handling and reconciliation

Design for out-of-order events, duplicate webhooks, partial fulfilment, cancellation after dispatch, address changes, failed delivery and returns. Each notification should reference the authoritative order version. If an event is older than the version already communicated, suppress or replace it according to a documented policy. Never send a “delivered” message merely because a courier event was received without validation.

Maintain a daily reconciliation between orders, send attempts, provider statuses and customer-visible states. Create support work for an order with no final notification after the expected window, and show the event history to the operator. Allow a customer to request the latest status without exposing another order tied to the same phone number.

Measure status freshness, duplicate-message rate, failed-notification recovery, opt-out handling and template errors. Conversion or repeat purchase should be analysed separately from operational delivery.
