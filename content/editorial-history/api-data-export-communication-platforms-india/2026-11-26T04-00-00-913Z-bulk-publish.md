# Communication API Data Export in India: Portability, Audit and Migration Design

*Research snapshot: 26 November 2026.*

**Editorial disclosure:** Export and retention requirements depend on contract, sector and law. This is an engineering and procurement framework, not a legal statement that every record is portable.

## Define the export inventory

List phone and WABA ownership, contacts, consent and suppression events, templates and versions, message IDs, webhook events, delivery states, recordings, transcripts, inbox users, roles, integrations, invoices and audit events. Mark each item as exportable, reconstructable, provider-owned or requiring a manual request. Do not assume that a dashboard download contains the raw event history needed to rebuild a workflow.

Keep customer data separate from credentials. Never export access tokens, signing secrets or private keys into a shared migration file. Rotate secrets and store the migration operator, date, purpose and destination.

## Use a stable schema

Create a mapping for tenant, external ID, event type, timestamp, source, status, consent purpose, language, template version and retention class. Preserve original provider IDs and add your own correlation ID. Validate ordering, duplicates, missing references, character encoding, time zones and redaction before importing into a new system.

## Migration rehearsal

Run a read-only export, sample records by channel and date, reconcile counts, restore into a sandbox and replay a synthetic webhook. Test a number change, template mapping, opt-out preservation, support history, duplicate event and failed import. Keep a rollback and customer-communication plan; a migration is not complete because a CSV downloaded successfully.

## Acceptance criteria

An export is usable when a second system can validate counts, preserve consent and suppression, map templates and users, retain original event IDs, reproduce a support timeline and reject duplicates. Sample recent and historical records, including failed messages and deleted or suppressed contacts. Record any provider-specific field that cannot be exported and make it part of the migration decision.
