# Agentic AI Permissions for Indian Businesses: Tool Access and Approval Gates

*Research snapshot: 26 November 2026.*

**Editorial disclosure:** This is an application-security and workflow design guide. It does not certify an AI system, vendor or business process.

## Classify tools by side effect

A read-only catalogue lookup is not equivalent to sending a customer message, changing a CRM record, issuing a refund or editing a payment instruction. Put tools into classes: read, propose, reversible write, external communication and irreversible or regulated action. The higher the side effect, the stronger the authorization, evidence and human review requirement.

NIST's [AI Risk Management Framework](https://www.nist.gov/itl/ai-risk-management-framework) is a useful public risk reference, but an organisation still needs its own owners, controls and tests. Least privilege should apply to the agent, tool credential, tenant and data returned by the tool.

## Permission decision model

Evaluate tenant, user or service identity, workflow, purpose, data classification, tool, requested arguments, approval state and expiry. Never let a model supply a tenant ID or permission level as trusted input. Validate arguments against the authoritative system and return a structured denial reason that the workflow can handle.

Use approval gates for money movement, identity changes, external commitments, sensitive data disclosure, mass outreach and destructive actions. Show the reviewer the exact payload and expected effect. An approval button for a vague “AI action” is not meaningful control.

## Audit, rollback and testing

Record run ID, model and prompt version, tool call, authorization decision, reviewer, result, rollback path and final business outcome. Test prompt injection, replayed events, expired approvals, cross-tenant access, partial failure and a tool returning stale data. Keep a kill switch and a queue of unresolved runs.

## Permission review checklist

Review every tool at least by action, data, tenant, expiry, approval and rollback. Keep separate credentials for development, staging and production. Test a prompt that asks the agent to reveal a secret, call a tool for another tenant, reuse an expired approval or change a protected field. The expected result should be a deterministic denial and an auditable event, not a persuasive explanation.
